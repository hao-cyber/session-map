# SessionMap 产品与设计宪章

> 状态：产品最高裁决文档。
>
> 本文档裁决产品含义、交互方式、视觉语言和实现取舍。功能规格、设计稿、
> 框架惯例或兼容性捷径与本文冲突时，以本文为准。

## 1. 北极星

当人同时驱动多个 AI Agent，真正稀缺的已经不是算力，而是人的注意力连续性。

终端和 session 记录了发生过什么，却没有保存：为什么走到这里？试过什么？
否定了什么？做了什么决定？现在卡在哪里？

SessionMap 把散落的对话持续整理成一棵以工作主线为核心的外置思维树。
Session 可以结束，思路不会丢，死路也不会被遗忘。

它最终只解决一个问题：

> **让人切回任何一条工作线时，3 秒找回当时的自己。**

对外英文定位：

> **SessionMap — the thinking map for coding agents.**

SessionMap 不是更漂亮的 session 列表，而是工作为何演变成当前形态的外置记忆。
它保存的不是一组被宣布为永真的结论，而是**不可抹除的思考轨迹，以及可随认识
修订的当前快照**。

## 2. 产品本体

一级对象是**工作主线**：一件语义连续的事。Session 只是观察来源，以及落在工作
主线内部的可移动光标。

```text
Session 对话记录
       │
       │ 模型进行语义理解
       ▼
工作主线 ─ 目标
           ├─ 尝试 ─ 死路及原因
           ├─ 发现
           ├─ 决策
           └─ 当前任务  ⌖ session 光标
```

以下本体不可退让：

- 一级节点是工作主线，绝不是终端 tab、进程、仓库、目录或 session ID。
- 一条工作主线可以跨越多个 session 和多个 agent 提供方。
- Session 只能通过模型的语义重判归属到另一条工作主线。
- 结构节点类型为 `goal`、`task`、`attempt`、`finding`、`blocker`、
  `decision` 和 `note`。
- 节点状态是当时被明确记录的判断：`active`、`waiting`、`resolved` 和 `dead`。
  后续认识可以推翻该判断，但必须通过带原因的关闭、替代或新分支留下修订关系，
  不能把旧判断原地改写得像从未发生过。
- `dead` 或 `resolved` 之后若因新证据重新可行，不把旧节点恢复为 active；新生长一个
  “因何重新采用”的方向。旧结论与后来的修订同时可见。
- 方向转折必须表现为：带原因关闭旧方向，再生长新方向。
- 死路永久保留。“为什么失败”是记忆的一部分，不是等待清理的垃圾。
- 每个相关 session 永远保留入口。终端还在时聚焦它；终端关闭时，同一个入口
  尝试恢复它。

## 3. 三秒恢复契约

打开或切回 SessionMap 后，用户应在三秒内依次回答：

1. **现在什么需要我？** 等拍板、等回复、等审阅、卡点，或没有紧急事项。
2. **这是哪条工作主线？** 看见工作对象，而不是产生记录的 session。
3. **为什么走到这里？** 看见最近的结构性转折、决策、发现和被保留的死路。
4. **从哪里继续？** 有一个可靠入口，能回到当前 session 或恢复已关闭 session。

任何视觉优化，只要推迟了上述答案，就是产品退化。

## 4. 裁决优先级

需求冲突时，按以下顺序裁决：

1. 北极星与三秒恢复契约。
2. 工作主线优先的本体与对象恒存。
3. 模型/runtime 边界和持久状态保证。
4. 可靠可供性与用户明确控制。
5. 注意力层级与空间连续性。
6. 分发便利和实现偏好。
7. 表面风格潮流。

典型裁决：

- 一个刚有动静的 session，不能仅因事件更多，就压过一条正在等用户拍板的主线。
- 已关闭 session 的入口只能变淡，不能消失。
- 某个框架即使更容易打包，只要削弱崩溃恢复，就是错误抽象。
- “Linear 风格”绝不等于到处使用紫色；状态色必须保有唯一语义。

## 5. 产品形态

### 5.1 唯一界面：本地网页

用户打开的产品是系统浏览器中的 **SessionMap**。本地网页不是诊断降级页，而是唯一
正式界面：它承载完整思维地图、状态、Fit、归档、撤销、跳转和恢复动作。

- 页面由回环 Bun 服务提供，默认不依赖公网、云账户或远程静态资产。
- 浏览器承担跨平台展示，不复制状态，也不在客户端重建业务模型。
- 界面必须使用足够大的稳定视窗保护空间记忆，不能退化成狭窄弹层或活动列表。
- “网页天然多端”只描述客户端材料；在设计远程认证和加密同步前，服务仍只绑定本机。

### 5.2 后台服务

Bun 编译的服务仍是唯一 runtime，负责监控 transcript、提取语义变化、串行写树
以及提供本地 UI。

- 服务可前台运行，也可由用户显式安装为用户级 launch agent，不依赖浏览器 tab 存活。
- `sessionmap open` 打开带一次性 fragment 引导的本地页面；页面不持久化第二份状态。
- 关闭浏览器不会清空、重建或遗失任何对象。

## 6. 信息架构

浏览器视窗由三层稳定结构组成：

1. **固定工具栏**：品牌、活跃 session 与更新时间、异常 workdir
   chip、归档入口、roll 引擎和服务健康度。
2. **Now 状态条**：紧凑、可横向扫读，先回答“现在什么需要我”；排序依据行动
   优先级，而不是装饰布局。
3. **地图画布**：工作主线及其思考结构，包含用户控制的稳定披露、几何缩放、
   session 光标和空间位置补偿。

地图中的稳定读取层级为：

1. **主题/工作主线**：找事的一级目录，由模型按语义归属；cwd、仓库和终端都不能
   代替这个判断。
2. **Session**：找入口的二级目录。每一行同时给出整段 session 的稳定主标题、
   最新进展小标题、实时终端状态，以及可展开的滚动脉络。
3. **滚动脉络与主题全貌**：默认退出阅读预算；需要追因时再展开。Session 脉络给
   2–6 个因果路标，主题全貌保留跨 session 的完整结构树。

Session 的 rolling snapshot 是从持久轨迹生成的**可变读取投影**：主标题概括整段
session，小标题只表达最新有意义的结果、卡点或下一步，脉络保留少量因果锚点。
模型发现旧理解不再成立时，应修订快照；runtime 只校验长度、形状和写边界。
快照不能替代底层轨迹，也不能因为一次重写而抹掉旧尝试、证伪原因或决策转折。

Now 状态条只是地图索引，不能长成另一套 dashboard，也不能把每个状态做成等权
大卡片。

工作主线按最近一次有意义的活动低频排序；同一主线内部保持结构稳定。卡点通过文字
和状态色获得显著性，不靠不断换位置吸引注意。

## 7. 视觉语言：明亮、安静、精确

### 7.1 三秒感知目标

用户第一眼应相信：

> “我的工作都还在，最需要处理的那条很明显，而且这个工具足够安静，可以整天开着。”

SessionMap 默认使用白色调。地图应像一张经过认真标注的工作台，而不是深色运维
监控屏。

我们借鉴 Linear 的密度、精确度、克制表面、快速反馈和安静 chrome，但不复制其
品牌、渐变或紫色主导的皮肤。

### 7.2 颜色所有权

色相只表达状态和新近度。分支身份永远不能用彩虹色编码。

| Token | 参考色值 | 唯一含义 |
|---|---:|---|
| 画布 | `#F7F7F8` | 稳定工作底面 |
| 表面 | `#FFFFFF` | 工具栏、浮层、抬升控件 |
| Hover | `#F1F1F3` | 可交互反馈 |
| 发丝线 | `#E4E4E8` | 留白不足时才使用的边界 |
| 分支线 | `#AAB2BE` | 全部树结构连线 |
| 主文字 | `#202124` | 工作主线与一级信息 |
| 次文字 | `#50525A` | 结构节点与细节 |
| 弱文字 | `#7D808A` | 已闭合、沉睡和元数据 |
| 等拍板 | `#B4233A` | 等待决策，最高行动信号 |
| 等待 | `#9A5B00` | 等回复、等审阅或等外部输入 |
| 运行中 | `#18734B` | Agent 正在工作 |
| 卡点/错误 | `#C2413B` | 阻塞或动作失败 |
| 5 分钟内 | `#6F55C7` | 仅用于二级新近度圆点 |
| 15 分钟内 | `#70839C` | 仅用于二级新近度圆点 |
| 焦点环 | `#586273` | 键盘焦点与选择，刻意保持中性 |

状态词是 runtime 当前观测或模型当前 ask 判断的明确记录，不因视觉衰减而消失；
新证据可以改变它，并留下对应更新时间。亮度和辅助新近度圆点可以衰减。红色不能
用于普通装饰。

未来可以增加深色主题，但必须保持相同的感知优先级并通过同一套交互测试；白色主题
始终是参考实现。

### 7.3 字体与网格

- 使用 macOS 系统字体族，通过 `-apple-system` 获得 SF Pro 和可靠的中文渲染。
- 只设四个功能层级：产品/主线、结构节点、状态词、元数据。
- 优先用字重和间距建立层级，避免依赖夸张字号差。
- 使用 4pt 基础网格，主要间距为 4、8、12、16、24、32pt。
- 工具栏控件高度保持 28–30pt；主要可点击行的有效命中高度至少 32pt。
- 圆角控制在 6–10pt；阴影只用于浮层，普通分组依靠留白和发丝线。

### 7.4 动效

- 唯一常驻运动是低对比度的 busy 呼吸点。
- 布局过渡为 160–320ms，只用于帮助眼睛跟踪空间变化。
- 归档、恢复和错误必须即时反馈。
- 系统启用“减少动态效果”时，停止呼吸并缩短过渡。
- 禁止装饰性 shimmer、粒子和持续流动的渐变。

## 8. 交互契约

一行的主体语义决定整行动作：

- 工作主线行：聚焦或恢复该主线最合适的 session。
- 带 session 光标的叶子行：聚焦或恢复该 session。
- 带子节点的结构行：折叠或展开。
- `Option` + 点击 session：Orca 可用时向它发话。
- 右键工作主线：立即归档，通过 toast 撤销。
- 双击真正空白的画布：适合视图。
- 拖动超过 5px 属于导航，绝不能误判为点击。

内容披露与相机导航必须分离：展开和折叠只来自用户对明确控件或结构行的操作，状态
以稳定节点 ID 为 key 持久化，并在数据刷新后保留。平移、缩放、Fit、窗口 resize 和
节点进入视窗都不得自动改变任何已有节点的展开状态。

系统只为首次出现、尚无用户选择的节点应用读取层默认值：主题和 session 目录可见，
session 脉络与主题全貌折叠。几何缩放只改变地图的观察比例，不改变树的拓扑或信息
层级；用户需要追因时，通过“脉络”或“主题全貌”明确展开。

刷新或重排后，把离视窗中心最近的节点钉回原位，保护用户的空间记忆。

## 9. 模型与 runtime 的边界

模型负责开放语义：

- session 归属哪条工作主线；
- 什么构成结构性转折；
- 用户正在被要求做什么；
- session 当前的整体摘要、最新进展和可展开因果脉络；
- 目标、尝试、发现、决策和卡点的具体标签。

Runtime 负责全部边界：

- ID 与 canonical 名称；
- schema 校验与 op 数量上限；
- 子树授权与 reattach 限制；
- 单写者串行化；
- offset、原子持久化和崩溃行为；
- capability 校验与全部副作用。

关键词、正则、cwd、分支或终端标题都不能决定语义归属。机械信号只能在模型确定
工作对象之后，用于定位 session 或终端。

## 10. 持久状态与对象恒存

思维树与 transcript offset 同住一个原子替换的 JSON 文件，执行器保持无状态。

持久层保存两种不同职责的数据：

- **不可抹除的思考轨迹**：记录当时走过的方向、判断、证伪、关闭原因和替代关系。
  “不可抹除”只表示记录不会被静默覆盖，不表示其中每个判断都永远正确。
- **可修订的读取快照**：为三秒恢复维护 session 主标题、最新进展与有界因果脉络。
  它可以被后续认识重写，是视图，不是历史的替代品。

提交顺序刻意采用 at-most-once：先消费 offset，再应用非幂等 grow。极窄崩溃窗口
最多丢失一次语义增量，绝不能重复生长分支。

SessionMap 改名迁移遵循：

- 新的 macOS 状态目录为 `~/Library/Application Support/SessionMap`。
- 已存在的 `~/.maintrail` 安装只迁移一次，不在旧树上原地修改。
- 只有新状态和新可执行文件准备完成后，才退出旧 launch agent。
- Schema 允许范围内，现有节点、死路、光标、offset、引擎选择和归档状态必须
  原样保留。
- 产品尚未公开，不长期保留 `maintrail` 别名；只保留状态迁移这座桥。

## 11. 本地信任与动作

- Transcript 只作为 append-only 输入，永远不修改。
- Runtime 资产全部 vendored；禁止 CDN、遥测和远程字体。
- 服务只绑定 `127.0.0.1`。
- 每个 `/api/*` 请求都需要私有 capability token；公开根页面不能泄露它。
  `sessionmap open` 通过不发送给服务端的 URL fragment 引导当前 tab，随后立即清理。
- 写请求强制回环 Origin、严格 JSON media type、object body 和 64KiB 上限。
- 跳转、恢复、归档、切换引擎和发话必须来自本地用户的明确动作。
- 标签、session 标题、prompt、git 字段和模型输出都是不可信渲染输入，必须同时在
  HTML 与 Markdown 边界转义。
- 不得为了远程或多端访问直接改成 `0.0.0.0`，也不得复用 capability 充当跨设备认证。

## 12. 分发与命名

统一名称：

- 产品：`SessionMap`
- CLI：`sessionmap`
- 后台可执行文件：同一个 standalone CLI binary
- GitHub 仓库：`sessionmap`

目标安装方式：

```bash
bun install --frozen-lockfile
bun run build
./dist/sessionmap install
./dist/sessionmap open
```

发布物是按目标平台构建的 standalone CLI；原生 App、Homebrew Cask、Developer ID
签名与 Apple 公证不属于产品路线。未来若增加包管理器分发，也只能包装同一 CLI 和
本地网页，不能引入第二套状态或界面。

## 13. 语言与文案

SessionMap 使用具体的工作语言，不使用 observability 黑话。

推荐：

- “等你选择发布方式”
- “音量假设已证伪”
- “终端已关闭，点击继续”
- “3 秒找回当时的自己”

避免：

- “Session orchestration dashboard”
- “AI-powered productivity intelligence”
- “调试进展”
- 只说“状态异常”，却不说明用户能做什么

节点标签描述工作或原因；界面文案描述下一步动作及其结果。

## 14. 非目标

SessionMap 不是：

- transcript 阅读器或全局聊天搜索器；
- token、成本或 agent 利用率 dashboard；
- 终端管理器替代品；
- 要求用户维护第二份事实源的任务管理器；
- 云端协作或遥测产品；
- 未经点击就向被监控 session 写入内容的自动 agent；
- 会用滚动摘要冲刷失败推理的工具。SessionMap 可以滚动更新读取快照，但完整轨迹
  必须继续保存被替代的判断和原因。

## 15. 验收证据

版本只有证明以下事实后才算完成：

1. 三个真实 agent session 同时做不同工作，即使 cwd 相同，也成为三条语义不同的
   工作主线。
2. 方向改变后，旧路径带原因闭合，新路径继续生长。
3. 服务重启后树与 offset 保持，且没有重复生长。
4. 终端关闭后入口仍可见；点击能恢复，或报告具体失败原因。
5. 每个主题下直接列出所属 session；每个 session 同时显示整体主标题、最新进展、
   实时终端状态和可展开的有界脉络。
6. 后续证据推翻旧判断时，读取快照会修订，而旧路径以关闭原因和替代关系留存。
7. 跨主线和畸形模型 op 被拒绝并记录日志。
8. Markdown/HTML 注入标签只按字面渲染。
9. 平移、缩放、Fit、resize 和刷新不改变用户披露状态；展开与折叠保持可预期且不破坏
   空间位置。
10. 归档、撤销与恢复不改变底层对象恒存。
11. standalone CLI 能安装或修复服务，`sessionmap open` 能进入授权后的同一棵树。
12. 白色主题浏览器截图通过层级、对比度、溢出、命中区、减少动态效果与空/错状态检查。
13. 回归测试、类型检查、Web 检查和编译 binary 冒烟全部通过。

## 16. 变更协议

任何涉及本体、产品优先级、对象恒存、颜色所有权、动作语义、状态持久性、
浏览器/服务职责或命名的改动，都必须在同一个逻辑变更中更新本文档。

临时发布步骤和短期实现备注属于其他文档；本文只记录长期有效的产品判断。
