# SessionMap 产品与设计宪章

> 状态：产品最高裁决文档。
>
> 本文档裁决产品含义、交互方式、视觉语言和实现取舍。功能规格、设计稿、
> 框架惯例或兼容性捷径与本文冲突时，以本文为准。

## 1. 北极星

当人同时驱动多个 AI Agent，真正稀缺的已经不是算力，而是人的注意力连续性。

终端和 session 记录了发生过什么，却没有保存：为什么走到这里？试过什么？
否定了什么？做了什么决定？现在卡在哪里？

SessionMap 把散落的对话持续整理成一棵以工作主线为核心的外置思维树。
Session 可以结束，思路不会丢，死路也不会被遗忘。

它最终只解决一个问题：

> **让人切回任何一条工作线时，3 秒找回当时的自己。**

对外英文定位：

> **SessionMap — the thinking map for coding agents.**

SessionMap 不是更漂亮的 session 列表，而是工作为何演变成当前形态的外置记忆。
它保存的不是一组被宣布为永真的结论，而是**不可抹除的思考轨迹，以及可随认识
修订的当前快照**。

## 2. 产品本体

一级对象是**工作主线**：一件语义连续的事。Session 只是观察来源，以及落在工作
主线内部的可移动光标。

```text
Session 对话记录
       │
       │ 模型进行语义理解
       ▼
工作主线 ─ 目标
           ├─ 尝试 ─ 死路及原因
           ├─ 发现
           ├─ 决策
           └─ 当前任务  ⌖ session 光标
```

以下本体不可退让：

- 一级节点是工作主线，绝不是终端 tab、进程、仓库、目录或 session ID。
- 一条工作主线可以跨越多个 session 和多个 agent 提供方。
- SessionMap 自动发现各 agent CLI 的可恢复会话记录；支持的对象必须来自该 provider
  用于原生恢复的完整 transcript / event log，而不是只含摘要、偏好或用户输入的 memory
  文件。Provider 没有可验证的持久会话与恢复协议时，不得伪装成已支持。
- Session 只能通过模型的语义重判归属到另一条工作主线。
- 结构节点类型为 `goal`、`task`、`attempt`、`finding`、`blocker`、
  `decision` 和 `note`。
- 节点状态是当时被明确记录的判断：`active`、`waiting`、`resolved` 和 `dead`。
  后续认识可以推翻该判断，但必须通过带原因的关闭、替代或新分支留下修订关系，
  不能把旧判断原地改写得像从未发生过。
- `dead` 或 `resolved` 之后若因新证据重新可行，不把旧节点恢复为 active；新生长一个
  “因何重新采用”的方向。旧结论与后来的修订同时可见。
- 方向转折必须表现为：带原因关闭旧方向，再生长新方向。
- 死路永久保留。“为什么失败”是记忆的一部分，不是等待清理的垃圾。
- 每个相关 session 默认永久保留入口，后台不得静默清理。终端还在时聚焦它；终端关闭时，
  同一个入口尝试恢复它。用户明确执行隐私删除时，删除该 SessionMap 记录并持久排除其
  provider + session 身份，防止 watcher 再次加工；原始 transcript 仍保持只读。
- 切换与恢复是核心动作：切换必须优先复用经 transcript 身份现场验证的现存终端；
  恢复必须使用原 provider、原始 session ID、原 cwd 和原生 resume 命令。任何歧义都
  明确停止，绝不能为了“看起来成功”而切错或新建错误会话。

## 3. 三秒恢复契约

打开或切回 SessionMap 后，用户应在三秒内依次回答：

1. **现在什么需要我？** 等拍板、等回复、等审阅、卡点，或没有紧急事项。
2. **这是哪条工作主线？** 看见工作对象，而不是产生记录的 session。
3. **为什么走到这里？** 看见最近的结构性转折、决策、发现和被保留的死路。
4. **从哪里继续？** 有一个可靠入口，能回到当前 session 或恢复已关闭 session。

任何视觉优化，只要推迟了上述答案，就是产品退化。

## 4. 裁决优先级

需求冲突时，按以下顺序裁决：

1. 北极星与三秒恢复契约。
2. 工作主线优先的本体与对象恒存。
3. 模型/runtime 边界和持久状态保证。
4. 可靠可供性与用户明确控制。
5. 注意力层级与空间连续性。
6. 分发便利和实现偏好。
7. 表面风格潮流。

典型裁决：

- 一个刚有动静的 session，不能仅因事件更多，就压过一条正在等用户拍板的主线。
- 已关闭 session 的入口只能变淡，不能被系统自动移除；用户明确删除是隐私控制，不属于静默消失。
- 某个框架即使更容易打包，只要削弱崩溃恢复，就是错误抽象。
- “Linear 风格”绝不等于到处使用紫色；状态色必须保有唯一语义。

## 5. 产品形态

### 5.1 唯一地图界面：本地网页文档

用户打开的产品是本机 Bun 服务提供的 **SessionMap 地图文档**。它不是诊断降级页，而是
唯一正式界面：承载完整思维地图、状态、归档、撤销、删除、跳转和恢复动作。系统浏览器、
浏览器安装式 Web App 和无状态 macOS 极薄壳可以承载同一文档，但不得形成第二套 UI。

- 页面由回环 Bun 服务提供，默认不依赖公网、云账户或远程静态资产。
- **任意本机浏览器直接可见是真正的产品能力。** 同一用户在本机使用任意现代浏览器、
  任意 profile 或新标签页直接打开固定地址 `http://127.0.0.1:4317/`，都必须立即读取同一
  Bun 服务中的真实持久状态；不得要求先运行 CLI、携带 URL 凭据、复用某个 tab 的
  `sessionStorage` 或展示演示数据。`localhost` 可作为等价别名，但稳定默认地址使用
  不受 IPv4/IPv6 解析差异影响的 `127.0.0.1`。
- 浏览器承担跨平台展示，不复制状态，也不在客户端重建业务模型。读取层只依赖标准
  URL fragment、Fetch 与本地披露偏好存储，不得绑定 Chrome、Safari 或某个 profile；
  默认浏览器和用户明确选择的任意现代浏览器必须进入同一协议。
- 支持的浏览器可以把同一固定地址安装为独立 Web App；macOS 安装包可以提供只含窗口
  管理的 WKWebView 壳。两者都必须加载 Bun 服务提供的相同资产和 API，不得复制状态、
  注入原生业务能力或绕过统一生命周期。
- 界面必须使用足够大的稳定阅读面保护空间记忆，不能退化成狭窄弹层或活动列表。
  默认读取面是可纵向滚动的主题与 session 目录；“地图”表达工作与思考的关系，不要求
  用户依赖二维拖动才能找到对象。
- “网页天然多端”只描述客户端材料；在设计远程认证和加密同步前，服务仍只绑定本机。

### 5.2 后台服务

Bun 编译的服务仍是唯一 runtime，负责监控 transcript、提取语义变化、串行写树
以及提供本地 UI。

- 服务可前台运行，也可由用户显式安装为用户级 launch agent，不依赖浏览器 tab 存活。
- `sessionmap open` 是打开浏览器并确认首帧可用的便利入口，不是访问授权前置条件。它打开
  带短期一次性 ticket fragment 的本地页面；页面登记回执、完成首次真实快照与地图渲染
  后确认 ready。只有收到回执，CLI 才能宣布打开成功。
- `sessionmap now` 是行动优先级索引的终端投影：用于快速判断、编号跳转或打开完整地图，
  不承担完整树阅读，也不创建第二份状态。
- 关闭浏览器、Web App 或 macOS 壳不会清空、重建或遗失任何对象。

## 6. 信息架构

地图视窗由两层稳定结构组成：

1. **固定工具栏**：品牌、活跃 session 与更新时间、异常 workdir
   chip、归档入口、roll 引擎和服务健康度。
2. **地图工作区**：宽桌面左侧先列需要用户行动的工作线，再列全部工作线；右侧以纵向
   页面滚动承载工作主线、主题脉络与 session 的稳定目录。每个主题只有一份脉络，按需
   展开为内联缩进大纲；session cursor 只作为其中的光标标记。主题脉络与目录共享同一
   页面滚动，不设第二套平移缩放导航。

地图中的稳定读取层级为：

1. **主题/工作主线**：找事的一级目录，由模型按语义归属；cwd、仓库和终端都不能
   代替这个判断。
2. **主题脉络**：主题拥有的唯一因果结构，默认以当前落点摘要退出阅读预算；需要追因时
   再展开完整结构树，跨 session 保留尝试、死路、决定、修订关系和所有 cursor。
3. **Sessions**：找执行入口的稳定目录。每一行同时给出整段 session 的稳定主标题、
   最新进展小标题、实时终端状态，以及“回到终端”或“恢复终端”入口。Session 不承担
   脉络披露或定位入口；脉络控制权只属于主题。

常态读取面就是主题与 session 目录。主题形成纵向 section，同一主题内的 session
形成稳定行；当一个主题包含很多 session 时，用户继续使用浏览器原生纵向滚动、滚动条
和键盘导航扫描目录。不得把抓住空白拖动画布作为寻找 session 的必要动作。当前主题标题
可以在其 section 内轻量吸顶，但不得与工具栏叠成挤压内容的多层 chrome。

宽桌面左栏由“待处理”和“工作线”两个读取分组构成。“待处理”只列等拍板、等回复、
等审阅与卡点，先回答“现在什么需要我”；“工作线”提供稳定的主题空间索引。两者都从
同一读取投影派生，点击只跳转 session 或滚动到右侧对应 section，不保存第二份状态、
不把 session 提升为一级。右侧仍保留完整纵向主题 section 与浏览器原生滚动。窄屏隐藏
冗余的全部工作线索引，但把待处理分组保留在目录上方。

**滚动优先是核心导航契约。** 页面纵向位置承担用户对“主题在哪、session 在哪”的空间
记忆；常态目录不得被二维画布、横向分页、逐主题翻页或独占 focus 页面替代。主题脉络
以缩进大纲内联展开，收起后仍回到原目录锚点。

主题行上的“脉络”按钮以缩进大纲展开该主题唯一的结构树，并原位变为“收起脉络”；
展开与收起都以主题 section 为归属边界，不切换页面、不建立返回栈，也不创建 session
私有脉络。展开大纲默认只揭示当前路径（活跃链与 session 光标祖先），其余子树保持
折叠。主题
标题行或行首折叠控件只展开、折叠 Sessions 目录，不连带改变主题脉络的披露状态；两者
使用独立、可恢复的读取偏好。

Session 的 rolling snapshot 是从持久轨迹生成的**可变读取投影**：主标题概括整段
session，小标题只表达最新有意义的结果、卡点或下一步，并保留少量有界因果路标供滚动
与兼容使用。Web 不把这些路标渲染为 session 私有历史；唯一权威脉络仍是主题树。
模型发现旧理解不再成立时，应修订快照；runtime 只校验长度、形状和写边界。
快照不能替代底层轨迹，也不能因为一次重写而抹掉旧尝试、证伪原因或决策转折。

Session 行可以展示由 runtime 验证的恢复情境：cwd、Git worktree、分支、创建时间与
更新时间。`cwd` 与时间来自持久 session；Git 信息是只读实时投影，不得写成持久语义、
参与主线归属或在 Git 不可用时伪造占位。

待处理分组是地图目录内的行动索引，不是独立状态条、dashboard 或活动 feed。运行中与
刚完成不等于需要用户行动，只留在工作线与 session 行内，不进入待处理分组。

工作主线按最近一次有意义的活动低频排序；同一主线内部保持结构稳定。卡点通过文字
和状态色获得显著性，不靠不断换位置吸引注意。

同一主线内的 session 按首次出现时间倒序形成稳定目录；已有 session 后续活跃、ask
或终端状态变化时不得换位。最后活动时间只作为弱元数据解释新近度，行动优先级继续由
左侧待处理分组与行内状态承担。顺序负责空间稳定，状态负责注意力，时间负责解释。

## 7. 视觉语言：明亮、安静、精确

### 7.1 三秒感知目标

用户第一眼应相信：

> “我的工作都还在，最需要处理的那条很明显，而且这个工具足够安静，可以整天开着。”

SessionMap 默认使用暖纸白色调。地图应像一张经过认真标注的工作台，而不是深色运维
监控屏；温暖的中性纸面是它的材质，不是装饰。

我们借鉴 Linear 的密度、精确度、克制表面、快速反馈和安静 chrome，但不复制其
品牌、渐变或紫色主导的皮肤。

### 7.2 颜色所有权

色相只表达状态和新近度。分支身份永远不能用彩虹色编码。

| Token | 参考色值 | 唯一含义 |
|---|---:|---|
| 画布 | `#F5F3ED` | 暖纸工作底面 |
| 表面 | `#FDFCF9` | 工具栏、浮层、抬升控件 |
| Hover | `#EDEAE1` | 可交互反馈 |
| 发丝线 | `#E3DED3` | 留白不足时才使用的边界 |
| 分支线 | `#A8A195` | 全部树结构连线 |
| 主文字 | `#26231C` | 工作主线与一级信息 |
| 次文字 | `#4F4B42` | 结构节点与细节 |
| 弱文字 | `#6F6A5E` | 已闭合、沉睡和元数据；小字号仍须保持可读 |
| 等拍板 | `#B4233A` | 等待决策，最高行动信号 |
| 等待 | `#9A5B00` | 等回复、等审阅或等外部输入 |
| 运行中 | `#18734B` | Agent 正在工作 |
| 卡点/错误 | `#C2413B` | 阻塞或动作失败 |
| 5 分钟内 | `#6F55C7` | 仅用于二级新近度圆点 |
| 15 分钟内 | `#70839C` | 仅用于二级新近度圆点 |
| 焦点环 | `#5D6470` | 键盘焦点与选择，刻意保持中性 |

状态词是 runtime 当前观测或模型当前 ask 判断的明确记录，不因视觉衰减而消失；
新证据可以改变它，并留下对应更新时间。亮度和辅助新近度圆点可以衰减。红色不能
用于普通装饰。

未来可以增加深色主题，但必须保持相同的感知优先级并通过同一套交互测试；白色主题
始终是参考实现。

### 7.3 字体与网格

- 使用 macOS 系统字体族，通过 `-apple-system` 获得 SF Pro 和可靠的中文渲染；品牌字标
  单独使用 New York serif 作为唯一装饰性字体锚点，正文与标题不使用 serif。
- 只设四个功能层级：产品/主线、结构节点、状态词、元数据。
- 优先用字重和间距建立层级，避免依赖夸张字号差。
- 使用 4pt 基础网格，主要间距为 4、8、12、16、24、32pt。
- 工具栏控件高度保持 28–30pt；主要可点击行的有效命中高度至少 32pt。
- 圆角控制在 6–10pt；阴影只用于浮层，普通分组依靠留白和发丝线。

### 7.4 动效

- 唯一常驻运动是低对比度的 busy 呼吸点。
- 布局过渡为 160–320ms，只用于帮助眼睛跟踪空间变化。
- 回到终端、恢复、归档和错误必须即时反馈；等待状态留在刚被操作的对象上，不能只在
  远处用 toast 告知。
- 系统启用“减少动态效果”时，停止呼吸并缩短过渡。
- 禁止装饰性 shimmer、粒子和持续流动的渐变。

## 8. 交互契约

- 工作主线标题行：单击或使用行首折叠控件，只折叠或展开该主题的 Sessions 目录。
- 工作主线行的“脉络/收起脉络”按钮：只控制该主题唯一脉络的披露状态。它与 Sessions
  目录折叠相互独立，用户不需要进入或退出 focus 模式，也不需要寻找返回按钮。
- Session 行不提供“脉络”或“定位脉络”按钮，单击也不改变脉络披露。行尾根据实时终端
  状态显示“回到终端”或“恢复终端”作为主要入口，并提供低显著的删除记录控制。
- Session 行双击：执行与行尾按钮相同的聚焦或恢复动作。双击只是加速手势，不能成为
  唯一入口。
- Session 行尾提供低显著的“删除 SessionMap 记录”。动作必须二次确认，并明确：原始 agent
  transcript 不会删除；记录将被持久排除，不会再次加工；若主题仍有其他 session，共享
  主题脉络因缺少可证明的逐字段来源归属而保留，若它是唯一 session 则主题脉络一并删除。
- 主题脉络中的 session 光标：聚焦或恢复对应 session。
- 带子节点的结构行：折叠或展开。
- `Option` + 点击 session：Orca 可用时向它发话。
- 右键工作主线：立即归档，通过 toast 撤销。

内容披露与目录滚动必须分离：展开和折叠只来自用户对明确控件或结构行
的操作，状态以稳定节点 ID 为 key 持久化，并在数据刷新后保留。页面滚动、窗口
resize 和节点进入视窗都不得自动改变任何已有节点的展开状态。

系统只为首次出现、尚无用户选择的节点应用读取层默认值：主题与 Sessions 目录可见，
主题完整脉络折叠；用户需要追因时，只通过主题行的脉络控件明确展开。

刷新、窗口 resize 或展开重排后，把离视窗上方阅读热区最近的稳定主题/session 行钉回
原位，保护纵向阅读位置。

## 9. 模型与 runtime 的边界

模型负责开放语义：

- session 归属哪条工作主线；
- 什么构成结构性转折；
- 用户正在被要求做什么；
- session 当前的整体摘要、最新进展和有界因果路标；
- 目标、尝试、发现、决策和卡点的具体标签。

Runtime 负责全部边界：

- ID 与 canonical 名称；
- schema 校验与 op 数量上限；
- 子树授权与 reattach 限制；
- 单写者串行化；
- offset、原子持久化和崩溃行为；
- 回环、同源请求校验与全部副作用。

关键词、正则、cwd、分支或终端标题都不能决定语义归属。机械信号只能在模型确定
工作对象之后，用于定位 session 或终端。

## 10. 持久状态与对象恒存

思维树与 transcript offset 同住一个原子替换的 JSON 文件，执行器保持无状态。

真实主题、session、脉络、快照、cwd 与 offset 只能写入 Git worktree 之外的本机状态目录。
即使用户显式传入 `--state-dir`，runtime 也必须拒绝仓库内路径；源码、测试、Web 资产与发布
产物只能包含明确标注的虚构 fixture，不得从真实状态生成或嵌入内容。

对象恒存约束系统的自动写入，不剥夺用户的隐私删除权。显式删除必须经统一单写者原子提交，
清除 session、其路径/cwd/读取快照、offset 与历史任务项，并留下最小化的持久排除标记。
删除发生时已在途的模型结果必须在提交闸门重新检查排除标记，不能让记录复活。

持久层保存两种不同职责的数据：

- **不可抹除的思考轨迹**：记录当时走过的方向、判断、证伪、关闭原因和替代关系。
  “不可抹除”只表示记录不会被静默覆盖，不表示其中每个判断都永远正确。
- **可修订的读取快照**：为三秒恢复维护 session 主标题、最新进展与有界因果路标。
  它可以被后续认识重写，是视图，不是历史的替代品。

提交顺序刻意采用 at-most-once：先消费 offset，再应用非幂等 grow。极窄崩溃窗口
最多丢失一次语义增量，绝不能重复生长分支。

首次安装必须先让用户决定历史覆盖范围，不得在确认前静默读取旧 transcript 正文或调用
模型。页面用 7 天、30 天、90 天和自定义起始日表达“把多早以前仍活跃的完整
session 带进地图”；用户也可以不导入历史。确认瞬间为所有已发现 source 建立 live
高水位，历史任务用独立耐久游标从头追到该边界，因此持续监听只处理确认后的新增内容，
历史范围可以以后向更早日期扩展而不会重复生长。30 天是基准推荐；若本机 30 天候选超过
20 个 session，界面改为推荐 7 天并明确提示任务较大。阈值仍需真实数据校准，不是心理学定律。

历史导入可暂停、续扫、取消并在服务重启后恢复；同一 session 内保持时间顺序，较旧背景
若在 live 内容之后才被补入，只能补背景与修订关系，不能用旧上下文关闭或重开当前路径。
用户确认后立即进入地图，历史导入默认退到后台；状态行和“历史进度”提供可见性，但进度卡
不得占住主阅读面。不同 session 可以有界并行整理，但同一 session 必须保持时间顺序；历史
不得占满全部处理能力，实时增量始终有保留槽且在排队项中优先。已经在途的一次模型调用不
强行中断，同 source 仍须先追平历史 high-water 才能保持顺序。并行模型结果只是候选，必须
经过单写者串行校验；依赖的主题语境变化后不得盲写旧结果。
常态仍由后台 watcher 持续运行。“立即检查”只触发一次 metadata discovery 与增量 poll，
不清 offset、不重跑模型、不扩大历史覆盖；扩大覆盖必须显式进入“补扫历史”。

SessionMap 改名迁移遵循：

- 新的 macOS 状态目录为 `~/Library/Application Support/SessionMap`。
- 已存在的 `~/.maintrail` 安装只迁移一次，不在旧树上原地修改。
- 只有新状态和新可执行文件准备完成后，才退出旧 launch agent。
- Schema 允许范围内，现有节点、死路、光标、offset、引擎选择和归档状态必须
  原样保留。
- 产品尚未公开，不长期保留 `maintrail` 别名；只保留状态迁移这座桥。

## 11. 本地信任与动作

- Transcript 只作为 append-only 输入，永远不修改。
- Runtime 资产全部 vendored；禁止 CDN、遥测和远程字体。
- 服务只绑定 `127.0.0.1`。
- 本机用户是默认信任边界：服务只接受回环 hostname 与回环客户端，且不提供 CORS。
  `/api/snapshot` 可由任意本机浏览器直接读取，不依赖 tab token；这保证换浏览器、换
  profile、新建标签页或手输固定地址时看到的都是同一份真实持久状态。
- `sessionmap open` 的短期签名 ticket 只用于 CLI 的首帧 ready 回执，不授予浏览器数据
  权限，也不把长期秘密放入 HTML、URL 或浏览器存储。CLI 查询 open 状态仍使用状态目录中
  权限为 `0600` 的私有签名密钥。
- 写请求强制回环 Origin、严格 JSON media type、object body 和 64KiB 上限。
- 跳转、恢复、归档、删除、切换引擎和发话必须来自本地用户的明确动作。
- 标签、session 标题、prompt、git 字段和模型输出都是不可信渲染输入，必须同时在
  HTML 与 Markdown 边界转义。
- 不得为了远程或多端访问直接改成 `0.0.0.0`，也不得复用本机 open 回执密钥充当跨设备认证。

## 12. 分发与命名

统一名称：

- 产品：`SessionMap`
- CLI：`sessionmap`
- 后台可执行文件：同一个 standalone CLI binary
- GitHub 仓库：`session-map`

非程序员默认安装方式：从 GitHub Release 下载已签名、公证的 `SessionMap.pkg`，双击后由
系统 Installer 完成安装，启动唯一 Bun 服务并打开 SessionMap 桌面窗口。开发者也可以使用：

```bash
brew install hao-cyber/tap/sessionmap
sessionmap install
sessionmap open
```

GitHub Release 是发布物的唯一事实源，提供经过原生架构验证的 standalone CLI、包含同一
CLI 与 universal 极薄壳的通用 macOS 安装包、校验和与来源证明。安装包、Homebrew Formula 和校验安装脚本
只能调用 `sessionmap install` 的统一事务；不得直接写用户状态、生成另一份 plist 或拥有
第二个服务生命周期。源码构建保留给贡献者。

发布链对 CLI、极薄 App 和 Installer package 使用对应的 Developer ID 证书并提交 Apple
公证，避免把 Gatekeeper 绕过步骤转嫁给普通用户。Electron 与拥有业务逻辑的原生客户端
仍不属于产品路线；任何新增分发渠道都只能承载同一 CLI 和地图文档，不能引入第二套状态、
写入路径或界面。

## 13. 语言与文案

SessionMap 使用具体的工作语言，不使用 observability 黑话。

推荐：

- “等你选择发布方式”
- “音量假设已证伪”
- “回到终端” / “恢复终端”
- “3 秒找回当时的自己”

避免：

- “Session orchestration dashboard”
- “AI-powered productivity intelligence”
- “调试进展”
- 只说“状态异常”，却不说明用户能做什么

节点标签描述工作或原因；界面文案描述下一步动作及其结果。

## 14. 非目标

SessionMap 不是：

- transcript 阅读器或全局聊天搜索器；
- token、成本或 agent 利用率 dashboard；
- 终端管理器替代品；
- 要求用户维护第二份事实源的任务管理器；
- 云端协作或遥测产品；
- 未经点击就向被监控 session 写入内容的自动 agent；
- 把菜单栏、通知、置顶或桌面常驻本身当成价值的监控客户端；极薄壳默认安静，只负责召回；
- 会用滚动摘要冲刷失败推理的工具。SessionMap 可以滚动更新读取快照，但完整轨迹
  必须继续保存被替代的判断和原因。

## 15. 验收证据

版本只有证明以下事实后才算完成：

1. 三个真实 agent session 同时做不同工作，即使 cwd 相同，也成为三条语义不同的
   工作主线。
2. 方向改变后，旧路径带原因闭合，新路径继续生长。
3. 服务重启后树与 offset 保持，且没有重复生长。
4. 终端关闭后入口仍可见；双击 session 或点击“恢复终端”能恢复，或报告具体失败原因。
5. 每个主题只有一份可展开的完整脉络并直接列出所属 session；每个 session 同时显示整体
   主标题、最新进展、实时终端状态和可靠终端入口，不显示脉络按钮。
6. 后续证据推翻旧判断时，读取快照会修订，而旧路径以关闭原因和替代关系留存。
7. 跨主线和畸形模型 op 被拒绝并记录日志。
8. Markdown/HTML 注入标签只按字面渲染。
9. 页面滚动、resize 和刷新不改变用户披露状态；主题的 Sessions
   目录与主题脉络可独立展开、折叠，session 动作不改变二者，目录保持可预期的纵向位置。
10. 归档、撤销与恢复不改变底层对象恒存；显式删除 session 会清除其本地记录并持久排除，
    重启、原 transcript 新增和在途 roll 都不能使它重现。唯一 session 的主题随之删除，
    共享主题脉络保留且确认文案不得声称已彻底擦除共享派生内容。
11. standalone CLI 能安装或修复服务；`sessionmap open` 只有收到页面首帧回执才报告
    成功。无需先运行 CLI，同一用户在本机任意现代浏览器、任意 profile 或新标签页直接
    打开 `http://127.0.0.1:4317/`，都能在首屏读取同一份真实状态；无数据时只能呈现真实
    空状态，不得注入演示数据。
12. `sessionmap now` 与页面待处理分组复用同一行动优先级投影，能从编号安全跳回 session；
    页面待处理只显示需要用户行动的项，同一主线不因明确 ask 与运行状态重复占两项。
13. manifest 安装入口、系统浏览器和 macOS 壳都加载同一地图文档；壳默认不置顶、不注入
    原生业务 API，关闭或崩溃不影响服务与状态。
14. 白色主题在代表性浏览器和 App 桌面截图中通过层级、对比度、溢出、命中区、减少动态
    效果与空/错状态检查。
15. 回归测试、类型检查、Web/Swift 检查、standalone binary 与 App 构建冒烟全部通过。
16. 全新状态在用户选择前只发现历史 metadata、不调用模型；跳过或选择范围后 live 高水位、
    历史游标和 coverage 可跨重启恢复，补扫更早范围不重复 grow，“立即检查”不改变 coverage。

## 16. 变更协议

任何涉及本体、产品优先级、对象恒存、颜色所有权、动作语义、状态持久性、
展示容器/服务职责或命名的改动，都必须在同一个逻辑变更中更新本文档。

临时发布步骤和短期实现备注属于其他文档；本文只记录长期有效的产品判断。
