# ADR 0010：主题脉络以缩进大纲呈现

> 状态：已采纳
> 日期：2026-07-20
> 替代此前读取层以 markmap 节点链接画布呈现主题脉络的做法；[ADR 0007](0007-theme-owned-lineage.md)
> 的“主题拥有唯一脉络”与 [ADR 0009](0009-theme-controls-lineage-session-controls-terminal.md)
> 的交互所有权分工继续有效。

## 背景与约束

主题脉络此前的呈现是 markmap 节点链接画布：58vh 局部视窗，`fit` 把整棵树缩放进视口，
配 pan / zoom / Fit 一套独立导航。真实使用中暴露三个有名字的问题：

1. **Overview 与 Readability 错配**：fit-all 把节点文字压到约 6px，默认状态不可读；
   大主题的脉络直接糊成色块。三秒契约要求默认状态即可读。
2. **Indented tree vs node-link 的任务适配**：HCI 研究一致表明，读标签、找节点、查清单
   类任务缩进大纲树优于节点链接图；后者只在“看拓扑全貌”时占优。脉络的任务是读因果链、
   找决策、看死路原因——纯标签阅读任务。
3. **与滚动优先契约的摩擦**：画布的 pan/zoom/Fit 是页面滚动之外的第二套导航制式，
   永远是外来者，还要单独维护点击/拖动判定、局部相机钉住等机制。

约束：主题拥有唯一脉络（ADR 0007）与“主题控制脉络、session 控制终端”（ADR 0009）
不变；披露状态继续以稳定节点 ID 持久化；不创建第二份持久状态。

## 决策

- 主题“脉络”控件展开的是**内联缩进大纲树**：每个结构节点一行（类型标记 + 标签 +
  关闭/阻塞原因 + session 光标），与目录共享同一页面滚动。
- 逐节点折叠复用既有披露体系（`manualFold` 按稳定节点 ID 持久化），带子节点的行
  显示 twistie，历史分组保持默认折叠。
- 首次展开且尚无用户选择时，默认只揭示**当前路径**（活跃节点链与 session 光标祖先），
  其余子树保持折叠（DOI 思路：当前节点 + 祖先为最高兴趣）。
- 退役画布的 pan / zoom / Fit / “适合视图”与点击拖动判定；markmap 仅保留其 Transformer
  作为服务端 markdown 的解析器，d3 与 markmap-view 不再加载。

## 备选方案

- **保留画布修阅读性**（默认 100% 缩放定位当前路径 + 路径高亮）：改动最小，但阅读
  天花板低，两套导航摩擦保留。
- **大纲 + 只读迷你概览图**：体验最全，但维护两套呈现与联动，当前规模下不划算；
  若未来脉络大到需要拓扑概览再评估。

## 后果

- 脉络阅读与目录共用滚动、选择与键盘导航；文字永远可读；死路与原因逐行可见。
- 失去拓扑全景感；接受这一代价（见备选方案）。
- 读取层删除整套画布事件机制；d3 / markmap-view 资产登记保留为后续清理项。
- `state.json`、TreeRuntime、披露偏好的存储键与回环安全边界均不改变；回滚只需
  恢复旧读取层代码，无数据迁移。

## 验证证据

- `tests/web-assets.test.ts` 断言大纲渲染、无画布导航机制、index.html 不加载 d3 与
  markmap-view。
- 代表性桌面截图：展开大纲逐行可读、当前路径默认揭示、twistie 与历史分组正确、
  与 Sessions 目录的归属边界清晰。
- 展开后页面滚动、resize 与刷新保持逐节点披露状态（本地存储持久化）。
