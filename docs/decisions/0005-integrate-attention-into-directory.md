# ADR 0005：把行动优先级整合进工作线目录

> 状态：已采纳
> 日期：2026-07-20
> 替代：[ADR 0004](0004-map-document-desktop-hosts.md) 中 Web 独立 Now 状态条的部分；
> 展示容器、`sessionmap now`、单写者与回环动作协议决策继续有效。

## 背景与约束

早期 Web 把 `buildNowItems` 渲染成工具栏下方的横向状态条，用于优先回答“现在什么需要
我”。当宽桌面加入稳定工作线侧栏后，横条与侧栏重复呈现工作线和状态，占用首屏高度，
视觉上又近似导航 tab，形成两套竞争的扫描路径。

三秒恢复契约仍要求行动请求先于完整目录被看见。删除视觉容器不能删除行动排序，也不能
让 busy/recent 这类无需用户介入的状态抢占“待处理”语义。Web 与 CLI 还必须复用同一份
服务端投影，不能增加客户端业务状态。

## 决策

- Web 删除工具栏与地图工作区之间的独立横向 Now 状态条。
- 宽桌面左侧目录顶部增加“待处理”分组，只显示 decision、reply、review 和 blocker；
  busy 与 recent 继续通过工作线/session 行内状态表达。
- 待处理分组之后是稳定的全部工作线索引。待处理项点击复用 session jump；没有可恢复
  session 的 blocker 只滚动到对应工作线。
- 窄屏隐藏冗余的全部工作线索引，但在正文目录上方保留待处理分组。
- `buildNowItems`、snapshot 的 `now` 字段和 `sessionmap now` 保持不变。Web 只在渲染时过滤
  非行动项，不持久化筛选结果或复制排序规则。

## 数据流与所有权

```text
state.json ─► buildNowItems ─┬─► Web 待处理分组（仅行动项）
                            └─► sessionmap now（完整快速投影）

Web 点击 ─► loopback /api/jump ─► ActionRouter
```

模型继续拥有 ask 的语义判断；runtime 拥有状态、优先级投影和动作边界；Web 只拥有布局、
响应式披露与同页滚动。左侧分组不是第二份任务列表。

## 失败、重启与安全

- Git、终端状态或局部渲染失败不影响持久 ask；刷新后从 snapshot 重建待处理分组。
- 没有行动项时明确显示“暂时无需处理”，不能用 busy/recent 填充出虚假紧迫感。
- 所有文本继续用 `textContent` 或服务端 escape 渲染；点击继续走同源回环动作 API。
- 回滚只需恢复旧 HTML/CSS/JS 展示，状态 schema 与持久数据无需迁移。

## 备选方案

- **完全删除行动索引**：页面更简洁，但用户必须扫描全部工作线，违反三秒恢复契约。
- **保留横向状态条**：信息完整，但与左侧目录重复并持续占用首屏。
- **把所有 busy/recent 也放进侧栏顶部**：保持旧投影原样，却模糊“需要我”与“系统有动静”。

## 验证证据

- Web 资产测试确认不存在 `#now-bar`，并存在待处理分组与行动项过滤。
- 投影测试继续证明 decision、reply、blocker、busy、recent 的共享优先级和去重行为。
- 代表性桌面截图检查左侧待处理、工作线与右侧目录的层级、溢出和首屏高度。
- 窄屏样式保留待处理分组并隐藏冗余工作线索引。

## 后果

页面收敛为“固定工具栏 + 左侧行动/工作线目录 + 右侧阅读文档”一个空间模型，首屏更高，
工作线不再横向重复。代价是 Web 与 CLI 对完整 `buildNowItems` 的展示集合不同；该差异是
显式产品语义：CLI 是快速状态投影，Web 待处理分组只回答需要用户行动的事项。
