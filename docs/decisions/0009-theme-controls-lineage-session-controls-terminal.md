# ADR 0009：主题控制脉络，Session 只控制终端

> Session 行“只出现终端动作”的部分已由 [ADR 0011](0011-explicit-session-deletion-and-repository-privacy.md)
> 补充：删除记录是独立的用户隐私控制，不改变主题/Session 的信息所有权。

> 状态：已采纳
> 日期：2026-07-20
> 替代 [ADR 0007](0007-theme-owned-lineage.md) 中由 session 定位主题脉络的交互部分。
> 脉络的呈现形式（画布 → 缩进大纲）由 [ADR 0010](0010-lineage-as-indented-outline.md) 决定。

## 背景与约束

ADR 0007 已把因果结构的所有权从 session 收敛到主题，但读取层仍在 session 行保留
“定位脉络”，并让单击 session 改变主题脉络披露。这让脉络的事实所有者是主题、交互所有者
却像是 session，用户也需要在“找思路”和“回终端”两种动作之间辨认同一行。

主题仍是一级对象，Sessions 仍是执行入口目录。用户必须能独立控制“是否查看这个主题的
因果结构”和“是否展开这个主题的 session 列表”，同时每个 session 的可靠终端入口必须
恒存。

## 决策

- “脉络/收起脉络”按钮只出现在主题行，只控制该主题唯一脉络的披露。
- 主题标题行或行首折叠控件只展开、折叠该主题的 Sessions 目录，不连带改变脉络披露。
- Session 行不显示“脉络”或“定位脉络”按钮，单击不改变任何披露状态。
- Session 行尾按实时状态显示“回到终端”或“恢复终端”；双击 session 行执行相同动作，
  只作为快捷手势。
- 主题脉络和 Sessions 目录使用同一主题 ID 下彼此独立的浏览器读取偏好；刷新、重启展示
  容器和页面滚动不得把二者联动。

## 所有权与数据流

```text
主题行 ──► 脉络披露偏好 ──► 主题唯一思考树
   └────► Sessions 披露偏好 ──► Session 入口目录
SessionRecord + monitor ───────► 回到终端 / 恢复终端 ──► /api/jump
```

`state.json`、TreeRuntime 和动作安全边界均不改变。两份披露偏好只属于展示容器，不进入
业务状态；session cursor 仍显示在主题脉络中，但 session 目录不再承担定位入口。

## 失败、重启、安全与回滚

- 主题脉络或 Sessions 目录缺失本地偏好时分别使用默认值：脉络折叠、Sessions 展开。
- 本地存储不可用时，两份偏好至少在当前页面生命周期内独立保持。
- 终端动作继续经过既有回环同源校验、进程身份现场验证和服务端在途去重。
- 若需要回滚交互，只恢复 Web 披露与事件绑定；没有 schema、状态文件或 transcript 迁移。

## 备选方案

- **Session 保留“定位脉络”**：定位精确，但继续混合思路阅读与执行入口两种职责。
- **主题折叠同时隐藏脉络与 Sessions**：控件更少，却无法独立回答“为什么到这里”和
  “有哪些可恢复入口”。
- **单击 session 直接回终端**：动作快速，但容易在浏览目录时意外抢走终端焦点；保留明确
  按钮与双击快捷方式更符合可靠可供性。

## 验证证据

- 文档与投影断言只有主题行出现脉络控件，session 行只出现终端动作。
- 浏览器交互证明主题脉络与 Sessions 目录可独立折叠并跨刷新保持。
- Session 单击不改变披露；双击和明确终端按钮执行同一动作且在途去重。
- 代表性桌面与窄屏截图检查按钮归属、标签、命中区、溢出和终端状态变化。

## 后果

交互所有权与信息所有权一致：主题负责“为什么”，session 负责“回到哪里继续”。代价是
session 不再提供 cursor 一键定位；用户在主题脉络中读取所有 cursor，换来更明确、稳定的
操作分工。
