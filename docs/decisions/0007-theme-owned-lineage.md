# ADR 0007：主题拥有唯一脉络，Session 只定位与恢复

> 状态：已采纳
> 日期：2026-07-20
>
> Session 定位脉络的交互部分已由 [ADR 0009](0009-theme-controls-lineage-session-controls-terminal.md)
> 替代；主题拥有唯一脉络、`snapshot.trail` 不作为 Web 历史等其余决策继续有效。

## 背景与约束

状态模型一直把工作主线作为一级对象：思考树挂在主题根节点下，session 只保存归属、滚动
快照和指向树节点的 cursor。旧读取层却把 `snapshot.trail` 展开在每个 session 行下面，另设
“主题全貌”。这种投影把同一主题的因果结构切成多份，看起来像 session 拥有脉络，并让
“有界 session 路标”和“完整主题树”竞争事实源。

三秒恢复仍要求用户能迅速看见当前路径、找到某个 session 所在位置并可靠回到终端；地图
目录仍以浏览器纵向滚动为主，不能把 session 提升为一级对象，也不能创建第二套持久状态。

## 决策

- 每个主题 section 只有一个“主题脉络”，直接位于主题标题下；它投影该主题根节点下的
  完整思考树，并显示所有 session cursor。
- Sessions 是与主题脉络并列的入口目录。Session 行继续显示稳定标题、最新进展、终端状态、
  cwd/Git/时间和恢复动作，但不再拥有或展开私有脉络。
- 有 cursor 的 session 行单击或点击“定位脉络”，展开同主题的唯一脉络、打开 cursor 的
  祖先路径、居中并短暂高亮对应节点。双击以及“回到终端/恢复”仍执行终端动作。
- `snapshot.trail` 暂时保留为模型生成的有界 session 读取快照，以兼容既有状态与滚动协议；
  Web 不把它渲染成第二条历史。权威因果结构始终是主题树。
- 主题脉络披露继续以稳定 `thoughts:<rootId>` 保存为浏览器读取偏好；cursor 定位和高亮不写
  入业务状态。

## 所有权与数据流

```text
主题根节点 ─► 唯一思考树 ─► Web 主题脉络
                              ▲
SessionRecord.cursor ─────────┘  定位/高亮
SessionRecord + monitor ─────────► Sessions 入口目录 ─► /api/jump
```

`state.json` 仍是树、session 和 cursor 的唯一事实源；TreeRuntime 仍是唯一写者；Web 只拥有
折叠、局部相机与短暂高亮。没有 schema 迁移、重复树或新的写入路径。

## 失败、重启、安全与回滚

- cursor 缺失或目标节点不存在时，session 的明确终端按钮仍可用，界面不伪造落点。
- 刷新或重启后从同一 snapshot 重建主题树和 cursor；短暂高亮可以消失，披露偏好按稳定 ID
  恢复。
- 所有内容继续经过服务端 escape 或 DOM `textContent`；定位只读取本页投影，不新增 API。
- 回滚只需恢复旧 Web 投影。保留的 `snapshot.trail` 让旧版本仍能读取既有状态，无数据迁移。

## 备选方案

- **继续在每个 session 下展开路标**：操作就近，但制造多个看似独立的脉络所有者。
- **删除主题树，只保留 session 路标**：目录简短，却丢失跨 session 的修订、死路和共同结构。
- **点击 session 进入独占脉络页**：定位明显，但破坏纵向空间记忆并引入返回栈。
- **立即删除 `snapshot.trail` schema**：概念最纯，但无必要地扩大迁移与模型协议风险。

## 验证证据

- 投影测试证明主题脉络先于 Sessions，session 不再产生 `snapshot-trail` 子行。
- Web 资产测试证明 session 单击定位 cursor，双击只跳转，明确按钮互不冒泡。
- 浏览器交互检查主题脉络展开、祖先揭示、节点高亮、行锚点和披露持久性。
- 代表性桌面与窄屏截图检查主题 → 脉络 / Sessions 的归属、溢出、命中区和对比度。

## 后果

界面与状态本体一致：用户先找到主题，再在一个共享脉络里理解“为什么到这里”，最后用
session 入口回到执行现场。代价是 session 的 2–6 个滚动路标不再直接显示；它们仍可服务
模型滚动和兼容，后续只有在独立证据证明无其他用途时才考虑 schema 迁移。
